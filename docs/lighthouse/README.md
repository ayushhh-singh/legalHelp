# Lighthouse reports

Generated by `pnpm lighthouse` (mobile, the default) and `pnpm lighthouse --preset desktop`.

## How these were measured

Against `scripts/serve-dist.mjs`, **not** `vite preview`. That matters: `vite preview` applies neither
`public/_headers` nor `public/_redirects`, so a run against it measures a site with no Content-Security-Policy,
no cache policy, none of the per-route preload hints, and no SPA fallback. `serve-dist.mjs` applies all four
and compresses, which is what Cloudflare Pages does.

Each run serves a **copy** of `dist/`, because a full run is seven routes and several minutes and a concurrent
`pnpm build` in the same working tree will otherwise replace the build mid-run.

Numbers from a CPU-throttled mobile run are only meaningful on an idle machine. A run taken while another
test suite was going measured `/pay` at 62 where a quiet run measured 85 — a 23-point swing that was entirely
contention. Check `uptime` before believing a regression.

The screenshots (`fullPageScreenshot`, the filmstrip, the final capture) are stripped before committing:
they were ~155 KB of a ~420 KB report and nothing here can be rebuilt from them that `pnpm lighthouse`
cannot rebuild locally. Every score, metric and audit result is kept.

**Accessibility, Best Practices and SEO meet the >= 95 target on every route. Mobile Performance does not**
— see `docs/DATA-GAPS.md` #58 for the measurement, the reason (Largest Contentful Paint, 89% render delay
rather than network) and the two options for closing it. ADR-030 records what was tried, including two
things that were measured and rejected.

Best Practices is 96 rather than 100 on `/` and `/learn` for one reason, and it is deliberate: those are the
two routes that load zod's schemas chunk, and zod probes for `eval` in a try/catch at import time. Under
`script-src 'self'` the browser refuses, zod catches it and uses its interpreted validator. Adding
`'unsafe-eval'` would buy 4 points and cost the policy (ADR-030, point 4).
